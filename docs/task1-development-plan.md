# Task1 / Dataset1 开发计划

更新：2026-11-03。计划依据：课程要求文件第 1、3-6 页，以及远程 `main` 的 `6a21653`。本文是开发建议和协作约定，不代表老师新增的要求，也不表示计划中的功能已经完成。

## 1. 目标与边界

Task1 是天气四分类：使用提供的 `train.csv` 学习，根据 `test.csv` 的 10 个属性预测 `label`，提交 `id,label` 两列。标签映射为 `1=Sunny, 2=Cloudy, 3=Rainy, 4=Snowy`。`id` 用于匹配记录，默认不作为特征。

主指标是四类等权的 Macro-F1：

```text
F1_k = 2 TP_k / (2 TP_k + FP_k + FN_k)
Macro-F1 = (F1_1 + F1_2 + F1_3 + F1_4) / 4
```

实现时固定 `labels=[1,2,3,4], average="macro", zero_division=0`。同时记录每类 Precision/Recall/F1 和混淆矩阵；Accuracy 只作为辅助指标。类别均衡也不意味着 Macro-F1 与 Accuracy 必然相等。

目标同时包含：

1. 在 Private Leaderboard 上争取最高排名。
2. 提供有实质算法细节的自主实现，清楚解释其准确率和效率设计。
3. 用可复现的对照、消融和误差分析支撑报告及展示。
4. 所有实际 Kaggle 提交，尤其最终选中的两份，都能从交付代码和配置重新生成。

本计划仅覆盖 Dataset1。Dataset2 的评分预测、RMSE、文本处理与分布式框架实现不在范围内。Spark/Hadoop 等框架的强制要求位于 Dataset2 的附加要求中，Task1 不必为此增加分布式系统。全组报告、演示和最终打包仍须与另一个任务的负责人协调。

不能保证第一名或满分：尚未取得榜单、竞争对手成绩和细化的名次计分规则。当前可操作的目标是持续改善稳健验证成绩、最弱类别和最终 Private 表现；不虚设 0.99 等满分门槛。

## 3. 已有基础：以最新 main 为准

### 数据事实

- 训练 9,900 条，四类各 2,475；测试 3,300 条。
- 7 个数值属性：Temperature、Humidity、Wind Speed、Precipitation (%)、Atmospheric Pressure、UV Index、Visibility (km)。
- 3 个类别属性：Cloud Cover（4 类）、Season（4 类）、Location（3 类）；现有独热编码共得到 18 个模型输入列。
- 无缺失值、完全重复训练特征记录或训练/测试完全相同特征记录。这不等于证明不存在近重复、分布偏移或噪声。
- 训练集中 Humidity 越出 [0,100] 的有 315 条，Precipitation (%) 有 294 条；不能简单相加作为异常行总数，因为可能重叠。
- 本地三个源 CSV 的完整 SHA256 与 `outputs/dataset1_custom/audit.json` 一致。原始文件保持不变。

### 尚未解决的问题

1. 没有统一 CV、系统调参、完整消融和最终候选选择协议；几个千分点的单次分数差不能确认模型优劣。
2. 自主森林训练 F1 约 0.9995、验证约 0.9134，需要分析泛化差距；不能仅凭这一点断定标签错误或泄漏。
3. 自主森林 Cloudy 的验证 F1 约 0.8836，为该模型最弱类别；需要在 CV 中复核，不仅针对此 Holdout 调整。
4. 样例的 `label` 为英文 `Rainy`，训练和 PDF 为整数；当前整数预测还不能直接视为有效 Kaggle 提交。
5. 现有 OOB 是共享预处理后的森林诊断，不能代替端到端 CV。
6. 计时来自协作者的 macOS 机器，不能当成本机计时；旧 baseline 与 custom 的计时口径不同。
7. 尚缺完整 CPU/内存等硬件摘要、正式提交生成入口、提交台账及最终复现验收。

## 4. 开发路线与验收标准

### P0：冻结数据、指标与提交接口

交付：数据审计复用、明确标签配置、提交校验及数据路径说明。

- 与竞赛 Evaluation/Data 页或课程官方说明核实输出编码，不能仅凭单个样例值猜测。首次合法提交须被平台接受且实际评分；记录最终采用的整数/英文格式及确认依据。
- 内部标签始终使用 1-4，导出时显式选择 `integer` 或 `name`，编码映射写入配置和元数据。
- 校验 `id,label` 两列、3,300 行、唯一且完整的样例 ID、按样例排序、无缺失或非法标签。检查使用显式异常，不能依赖可被 `python -O` 关闭的 `assert`。
- 数据目录由 CLI 参数指定，本地可使用仓库外 `../Dataset`；不把个人绝对路径写入协作配置。
- 更新审计时检查近重复、异常交集、类别字符串及训练/测试分布。若发现实际组结构或重复族，再改用分组验证；不能凭顺序 ID 假设时间关系。

验收：合法输出可被校验器读回；错误 ID、漏行、错编码必须失败；原 CSV 哈希不变。

### P0：建设统一验证和实验记录

建议新增 `code/task1_cv.py`、`code/task1_submission.py`、`configs/task1/` 和对应流程测试。以上为拟新增文件，当前尚未实现。

1. 固定按 ID 排序的输入、数据 SHA256 和分层 5 折规则，主 seed=5434；所有模型复用相同折号。记录折号摘要哈希和算法/依赖版本，以便双方复建一致划分。
2. 每折单独拟合填补、编码、缩放、特征选择和其他依赖训练数据的变换。禁止在全量训练数据先生成有标签统计再 CV。树模型可比较不缩放；线性/距离模型保留必要缩放。
3. 每条训练记录在一轮 5 折中恰好得到一次折外预测（OOF）；固定概率列顺序 `[1,2,3,4]`，检查有限、非负且每行和为 1。
4. 输出每折 Macro-F1、均值、标准差、全体 OOF Macro-F1、各类指标、混淆矩阵、训练/推理时间和配置。
5. “折分数均值”和“汇总 OOF F1”分开命名；标准差不是置信区间。不同计时必须说明是否包含预处理。
6. OOF 明细留本地，版本库保存小型汇总、配置、折规则、图表和哈希。
7. 对前 2-3 个候选用预先登记的额外 seeds=2026、1170 复核稳定性；不得只展示最好的 seed。

开发 CV 用于选模，不宣称是无偏最终表现。已有 Holdout 已反复用于探索，不能重新命名为独立测试集。

最终只对少量候选执行冻结的 5 外折 × 3 内折评估：超参数选择、Early stopping、融合权重、类别倍率均在外层训练部分内决定，外层验证只评估。内部搜索预算预先固定，并记录。此举降低选择偏差；由于已经存在全数据上的探索，不宣称对整个研究过程提供完全独立、无偏的最终估计。官方 Private 成绩才是最终评分依据。

额外 seeds 与嵌套评估是增强证据的建议，不是老师明示要求。先完成统一 5 折、正确 OOF/融合隔离和最终复现；将最终评估限制在 1-2 个冻结配方，每组先预估用时并设置不超过一个夜间窗口（建议 8 小时）的预算。超预算时减少候选/内层搜索或只复核一个额外 seed，保留训练与评估隔离并如实披露，不能挤占交付复现时间。

验收：双方同数据/代码/配置产生相同折哈希；训练与验证 ID 不相交；每条 OOF 恰好一次；单独测试确认预处理看不到验证部分。

### P1：改进自主森林，并保留清晰的算法解释

先复核已有正确性测试，在统一 CV 中再评估现有 CART/RF；保留现有代码作为可工作的回退方案。

建议搜索空间（是实验预算，不是必须穷举）：

| 参数 | 初始候选 | 目的 |
| --- | --- | --- |
| `n_estimators` | 100，300；曲线有收益才扩展 500 | 降低方差与观察饱和 |
| `max_depth` | 6，8，12，16，None | 控制树复杂度 |
| `min_samples_leaf` | 1，2，4，8，16 | 控制叶概率方差 |
| `max_features` | sqrt，0.5，1.0 | 平衡单树强度和树间相关性 |
| `min_impurity_decrease` | 0，1e-5，1e-4，1e-3 | 抑制无收益分裂 |
| `bootstrap` | True；False 用于受控对照 | 检验样本扰动作用 |

先用固定 3 折筛选 20-40 个随机配置，再将前 3-5 个配置置于统一 5 折完整比较；筛选结果不能冒充最终 5 折结果。设置每组运行上限并缓存安全的折内变换，避免全参数笛卡尔积。

优先扩展的自主设计：

- 原始属性级随机采样：现有 `max_features` 在独热编码后的 18 列中采样。可以先抽原始 10 个属性，再允许该属性对应编码列参与切分，检验类别属性占用多列产生的影响。
- 比较叶概率平滑 `(count_k + alpha) / (n_leaf + 4 alpha)`，alpha 取 0、0.5、1；验证集成概率和类别 F1 是否改善。
- 在有时间且基础方案稳定后，试验自主随机阈值树（ExtraTrees 思路）或直方图切分。说明改变了候选阈值搜索，不把简单换类名当作自主贡献。

上述扩展均应有算法测试和有/无消融。优先做出一个有稳定增益的设计，不为增加术语堆积实现。

效率设计应围绕现有累计计数和向量化：记录排序/切分热点、节点数、树数、内存；必要时再做树间并行。报告 CPU/服务器/线程数，避免并行树再叠加过多 BLAS 线程。所有加速须验证概率与原版本一致或解释算法近似。

验收：正确性测试通过，统一 5 折可运行；至少保留一个有完整配置和时间记录的自主候选。未提升的设计也保留实验结论。

### P1：比较更强候选，建立排名上限参照

与自主路线并行，按同一验证协议比较：

1. HistGradientBoosting：已有基线，优先调整学习率、叶数量、叶样本、L2 与迭代数。
2. CatBoost：直接传原始类别列，使用其类别处理能力，不沿用给其他模型的外部独热编码；内部训练损失可为 MultiClass，候选评价以外部统一 Macro-F1 为准。
3. 自主/库随机森林和额外随机树：检验误差互补。
4. 仅当前几类停滞且预算允许时，再加入 LightGBM/XGBoost 或距离模型。当前数据规模不要求 GPU，也不优先投入大型深度网络。

CatBoost 优先试验深度 4/6/8、学习率 0.02/0.05/0.1、L2 1/3/10，给定迭代上限；迭代数由训练部分内部验证确定。先粗搜再收敛，不对所有组合全部训练。

这些是基于表格数据特性的候选建议，不是已经验证会胜出的结论。低基数类别也可能让简单独热编码树表现很好。

库模型可用于强对照及最终方案组件，但应保留自主实现和独特设计的实质作用，并用消融说明。若最终完全弃用自主核心而只剩库分类器，应核实其与课程黑箱要求的符合程度，不能承诺不扣分；不能为了形式合规强行加入已证实降低泛化的模型。

验收：每个保留模型均有同折 CV、完整参数、依赖、时间和用途说明。强模型没有稳定提升则回退，不把模型名称当成效果证据。

### P1：清洗、特征和错误分析

先保留原值作为参照，按同折比较以下策略：

| 组别 | 对照 |
| --- | --- |
| 百分比异常 | 原值；截断到 [0,100]；原值+越界标记；截断+越界标记 |
| 特征组合 | 基础 10 属性；少量温度×湿度、温度×季节、云量×UV、气压×降水候选 |
| 类别编码 | 各模型合适的编码；必要时比较原始属性级采样 |
| 概率 | 原始叶概率；平滑概率；有依据时再做校准 |

物理不合理不等于无预测价值；不能直接删异常行。若学习分位数、离群阈值或监督编码，必须只使用当前训练折。当前类别均衡，不默认使用 SMOTE 或额外类别权重。

错误分析以 OOF 为主：Cloudy 与哪些类混淆、异常样本与正常样本差异、季节/位置分组表现、低置信度与高置信度错误、不同模型错误交集。小样本子组同时展示样本数，避免对少量例子过度推论。

现有不纯度重要性不是因果贡献。可在冻结候选后补充折外 permutation importance，或按属性组移除消融；用于进一步选特征时仍属于开发活动，需要在后续评估中反映选择过程。

验收：至少一张分组误差表和一组清洗对照；每个“更好”的结论都有同折分数及时间。没有效果的特征及时移除。

### P1：自主概率融合与 Macro-F1 决策

只融合 2-4 个表现强、错误互补的模型。先比较单模型和简单平均，再尝试自主非负权重概率融合：

```text
p_ensemble(k|x) = sum_m w_m * p_m(k|x), w_m >= 0, sum_m w_m = 1
prediction = argmax_k p_ensemble(k|x)
```

用小网格或受约束随机搜索寻找权重，避免复杂二层模型的额外方差。必要时试验有限、靠近 1 的类别倍率，直接围绕 Macro-F1 优化决策；类别均衡时仍可能有效，但不预设一定提升。

严格区分：基模型的 OOF 对其训练是折外的，但在整份 OOF 上选权重后，同一份 OOF 的最优分数已经是调参结果。不能将其直接当成无偏集成收益。

最终评估中，每个 outer-train 内产生 inner OOF，学习权重/倍率；仅将已冻结的选择应用到 outer-valid。Early stopping 也不看 outer-valid。选定最终配方后，才在所有训练数据重新生成 OOF 学习最终权重并重训基模型，或使用与评估一致的折模型平均。全量重训与折模型平均是两个不同候选，须记录哪种方法生成了提交。

验收：最终混合的选择过程与评估过程隔离；跨折/额外 seeds 的收益可信，否则采用最强稳定单模型。报告必须展示去掉自主组件及去掉其他组件的实际影响。

### P0：正式提交、可复现交付

每份提交至少关联：代码 commit、配置文件及哈希、数据 SHA256、标签编码、训练种子、折规则、模型组合、CSV SHA256、再生成命令、本地指标、Kaggle 提交编号/时间/Public 分数、是否选中和选择依据。不要把原始 ID/预测行写进仓库台账。

每天最多 10 次是上限，不是需要用满的预算。通常每天 1-3 个有明确假设的候选足够；保留故障修复额度。不要根据公榜做大量类别倍率/种子试探，也不从外部同源数据寻找测试标签。

截止前主动选两份经验证的提交，例如一个稳健单模型/自主方案与一个有可信增益的互补融合；如果相同配方的两个 seed 几乎完全一致，第二份没有提供多少分散风险的价值。不能为了“不同”选择明显更弱模型。

另一位协作者从干净环境执行完整流程，验证最终 CSV 哈希一致。固定软件版本、随机种子和线程设置；跨平台若不能字节一致，调查数值差异并确定正式复现环境，不在差异未知时宣称完全复现。

树模型训练时间按 fit/树数报告，epoch 写不适用；迭代提升模型可以报告迭代数和平均迭代时间。统一报告预处理、训练、全部离线流程和 3,300 条测试推理时间；搜索总耗时与最终训练耗时分开。

## 5. 最低实验矩阵

| 实验 | 比较内容 | 必须回答的问题 |
| --- | --- | --- |
| E01 | 现有 baseline/custom 的统一 5 折 | 单次排序能否稳定复现？ |
| E02 | CART → Bagging（全特征）→ 随机森林 | 样本扰动与节点特征随机性各有多少贡献？ |
| E03 | 树数 50/100/300，必要时 500 | 准确率收益何时饱和，时间如何增长？ |
| E04 | 原值/截断/标记组合 | 脏数据处理是否真的有益？ |
| E05 | 基础属性/少量组合/属性组随机化 | 新设计是否改善泛化？ |
| E06 | 自主模型/参数匹配库模型/强提升模型 | 自主实现的有效性、效率与上限差距是什么？ |
| E07 | 最强单模型/简单平均/学习权重 | 互补误差能否产生稳定增益？ |
| E08 | 融合中逐个去掉组件、去掉倍率 | 自主与其他组件究竟贡献多少？ |
| E09 | 冻结配方的额外 seeds/外层评估 | 收益是否只来自一次划分或调参偏差？ |
| E10 | 干净环境从零到最终 CSV | 提交能否被交付代码重建？ |

每组只改变目标因素，使用相同折；除目标因素及其直接成本（如树数）外，其余训练设置与计时口径一致。所有可能的完全交叉组合不是必须；优先完成能回答明确问题的比较。
